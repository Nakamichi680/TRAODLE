# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

TRAODLE is a Windows console tool (Visual C++) that unpacks and converts Tomb Raider game assets into Autodesk formats: **FBX (ASCII)** and **Maya ASCII (.ma)**, plus textures (DDS/TGA/BMP). Code comments and commit messages are in Italian.

At startup it asks for a mode on stdin:
- `0` – Tomb Raider Anniversary Edition: `CLUSTER` → LVC (geometry), TEXSET (textures), MDC (models)
- `1` – Tomb Raider: The Angel of Darkness: `.GMX` or `.GMX.CLZ` → RMX (rooms; each room group gets the custom attributes `roomIndex` (locked) and `visibleRooms` (space-separated indices of the rooms set in its room visibility mask, editable), also written as FBX user properties), ZONE (room geometry; zone objects are slots made of several meshes in a parent/child hierarchy (`TRAOD/ZONE/ZONE_Objects.cpp`, see `ZONE_Struct.h`), exported with their hierarchy as RMX `PS2_ROOM_OBJ` instances (static objects, layer `<LEVEL>_Z&&_Objects`) and RMX `RMX_OBJECT` nodes (interactive objects: doors, drawers, cars, ..., slot in `RMX_OBJECT.ZoneSlot`, layer `<LEVEL>_Z&&_Interactive`, attributes `objectIndex` = object class, `rmxNode` = node hash and, when the slot holds the meshes of an animated object, `animatedObject` = its CHR name), both with world position/rotation XYZ/scale, as Fakes, or, when nothing places them, as Items on a grid next to the level; object collisions (CLN triangle format, `ZONE_ExportCollision`) are exported inside the object hierarchy in the hidden layer `<LEVEL>_Z&&_Object_Collisions`, and only exist in interactive objects), RMX emitters (box/line/point volumes with `effectTemplate` from WorldEdit's `effects.fsc` matched by hash, color and raw parameters, `TRAOD/RMX/RMX_Effects.cpp`) and triggers (volumes with `actions`/`messages` attributes, plus `<LEVEL>_TRIGGERS.txt` in `\Scripts`), CAM, CBH (in-game cameras: fixed shots activated by RMX triggers (`trackingMode` 1 = looks at its target, 0 = looks at Lara's head) and rails (position-driven, not timed: the game projects Lara on the polyline of the rail cameras' `RailTarget` points and linearly interpolates eye/target/roll/fov between consecutive cameras, `CameraRail_NearestCameraOnTrack`), `TRAOD/CAM/CBH_Struct.h` = the runtime `CAMERA_FILE`, exported by `Export_CBH` to `\Cameras\<LEVEL>_GAME_CAMERAS.MA/.FBX` as groups `<LEVEL>_GCAM_<i>[_<trigger>]` with the camera as child, a `_Target` locator and attributes cameraIndex/trackingMode/trigger/roll/fov/target*/railTarget*/nextCamera, rails as `<LEVEL>_RAIL_<k>` with a path curve; the game view (`mathLookAt`, also used for CAM cutscene cameras) looks exactly at the target with up = world Z rotated by roll degrees around world Y, reproduced by `CAM_GameCameraRotation` for both CBH and CAM (Maya rotate order XYZ, angles kept continuous between frames; the old CAM formula `atan(tan(roll) cos(rotZ))` was exact only for horizontal cameras); note that `FBX_Export` does not write `FBX.Animation`, so the CAM FBX holds only the first frame and the animated camera is in the MA), CLN (collisions), SCX (scripts: each contains Small 2.x AMX bytecode, exported as `.amx` + disassembly `.asm` + decompiled pseudo-Pawn `.p` by `TRAOD/SCX/`; the `.p` is meant to be recompiled by TRAODLI, so it must contain every cell of the data section: 2D arrays (row table + rows, accessed as `base + 4k + mem[base + 4k]`) are declared `g_XXXX[rows][cols]`, unreferenced cells as `// unreferenced` variables, floats with the shortest exact text, strings with the Small 2.x escape `^` (`#pragma ctrlchar '^'`) and `!` for packed strings; the `// Data section` line and the log report the coverage; an English disclaimer at the top warns that types are deduced), EVX (event groups: sequences of `NM_*` map messages, exported as readable `<NAME>_EVENTS.txt` in `\Scripts` by `TRAOD/EVX/`, targets described from the RMX node list), scripted camera sequences ("maya tracks": a trigger script calls `Camera_SetScriptCamera(track, frame)` every frame; the track is a 2D float array in the script data, rows of 8 floats eye xyz/target xyz/fov/roll sampled at 60 fps, the game uses every second row; `TRAOD/SCX/SCX_CameraTracks.cpp` exports them like CAM cameras through `CAM_BuildAnimatedCamera` to `\Cameras\<script>.MA/.FBX`), CSS (cutscene subtitles: start frame, duration and text-database key of each line at 30 fps, exported as `<CUTSCENE>.txt` in `\Subtitles` by `TRAOD/CSS/`), CHR (characters: skeleton + skinned meshes + materials/textures + face blend shapes from the level's TMT files + facial animations from the TMS/".3" files, including those of other TMTs of the same face whose targets are the same in a different order (`CHR_Morph.remap`): FBX takes in the character FBX, one MA per animation in `\Animations` referencing `..\Characters\<CHR>.MA`, `TRAOD/CHR/`; CHR files starting with "NODE" are animated objects (doors, drawers, levers, ...: `TRAOD/CHR/CHR_Nodes.cpp`, format in `CHR_Struct.h`): only Maya transforms with pivots/rotate axis and push/pop hierarchy flags, no geometry; their meshes are the ZONE object meshes with the same name (hash of the uppercase node name) in the slot that matches most nodes, exported to `\Characters\<CHR>.MA/.FBX` with one group per node (pivots written as Maya `.rp/.sp/.rpt/.spt/.ra` and FBX RotationPivot/ScalingPivot/RotationOffset/ScalingOffset/PostRotation = inverse of the rotate axis) in the slot's pose (the level pose)), CAL (skeletal animations, `TRAOD/CAL/Export_CAL.cpp`: one MA per animation referencing `..\..\Characters\<CHR>.MA` with namespace, reference node and curve names taken from the animation name, so several actors sharing a CHR (e.g. STRAHOVA_1/STRAHOVA_2 in CS_6_2) can be loaded together as separate characters; after all exports `Export_CutsceneScenes` (`TRAOD/CAL/CAL_CutsceneScene.cpp`) writes `\Animations\<CUTSCENE>.MA` for every cutscene with a CAM or POS file, referencing every `<NAME>_<CUTSCENE>.ma` animation (namespace `<NAME>`, plus a `-rdi 2` line for the character/object each animation references, otherwise Maya leaves nested references unloaded) and `..\Cameras\<CUTSCENE>.MA` (namespace CAMERA), timeline = longest of camera and animations plus a single `<CALNAME>.FBX` (skeleton + one take per animation) in `\Animations\<CALNAME>`, plus `<CALNAME>_TRANSITIONS.txt` (`CAL_ExportTransitions`, written for every CAL: per animation flags, altanim, CAL_LINK raccordi and CAL_BLENDRANGE/BLENDCLIP windows, then the CAL_LINKPATH table, every animation as `NAME(0xHASH)`, times in frames at full float precision; these rules were authored in AnimEdit and cannot be derived from the curves, so the file is what an importer needs to rebuild them); root motion is combined into the root joint (HIP), never on the character group, which parents the skinned meshes; a CAL named like a NODE CHR, or matching no character, animates the object instead: track i = node i, absolute translation, quaternion /16383, scale /255, `CAL_ExportObject`). AoD file layout: in levels `<CHAR>.CAL` holds the game animations shared by all models of the character (LARA.CAL for LARAD, LARAC1, LARAC2, ...) and `<CHAR>_DLG.CAL` the dialog animations, which start the facial sequences of the `.3` files through FIRE_MORPH_TRIGGER keys on the base TMT (`<CHAR>.TMT`); cutscenes (`CS_*` levels and `IG_*` in-game cutscenes inside normal levels) use per-actor `<CHAR>_<CUTSCENE>.CAL/.TMT/.TMS` plus `<CUTSCENE>.POS` (world position of every actor's HIP per frame, `TRAOD/CAL/POS_Struct.h`, matched by `CAL_ANIMATION.animID`), always applied to the reference CHR (LARAD, LARAC1, ...). The CHR is matched by name and animated-bone count; the cutscene MA replaces the blend shape targets of the referenced character with the cutscene TMT through `setAttr` reference edits. Attached objects (weapons, holsters, ...: node groups in the CHR between header and skeleton, `CHR_Read_Attachments`, exported as `<CHR>_ATTACH_<NODE>` transforms under the attach joint; animated MESH2 = node meshes) are animated by the CAL ParentTracks; MAKE_VISIBLE / MAKE_INVISIBLE keys become visibility curves (MA only) on attached nodes and MESH2 meshes. Cutscene objects (`OBJECTnn_<CUTSCENE>`, NODE CHR) get their per-frame world position and visibility from `<CUTSCENE>.XXX` ("PPOS", `TRAOD/CAL/XXX_Struct.h`, matched by animID) on the object root group. Cutscene switches (`<CUTSCENE>.TXT`, read by the game's `CS_Initialise`, `TRAOD/CSS/CS_Switches.cpp`): `#MAP WORLD OFF` lists RMX object nodes hidden during the cutscene (game sets ObjFlags 0x2000000; exported as the `cutsceneOff` attribute on the ZONE object instances), `#CHAR <ACTOR> OFF` lists attached objects/meshes (by hash) of the map character `__<actor>` hidden at the start of the cutscene (visibility 0 from frame 0 in the `<ACTOR>_<CUTSCENE>` animation, before the CAL visibility keys), `_NO_CULL_` sets CHARFLAGS_NOCULL; the clean text goes to `\Cameras\<CUTSCENE>_SWITCHES.txt`. Other events and FX nodes are not exported. Also asks for target renderer (`TargetRenderer`: 1 = Maya Hardware 2.0, 2 = Arnold), which changes how materials are exported.
- `2` – AoD Remastered: `.MSH` → mesh

The input file path is `argv[1]` (typically drag-and-drop onto the exe). Output is written into a folder named after the level next to the input file (`\LEVELNAME\Rooms`, `\Zones`, `\Cameras`, `\Collisions`, ...), plus a log file.

## Build

Single-project solution `TRAODLE.sln` → `TRAODLE/TRAODLE.vcxproj`. There are no tests or linters.

```
msbuild TRAODLE.sln /p:Configuration=Release /p:Platform=x86
```

- Only the **Win32** configurations are fully set up (precompiled header creation via `TRAODLE.cpp`, `_CRT_SECURE_NO_WARNINGS`, absolute include dir `D:\AoD\C++\VISUAL C++\TRAODLE\TRAODLE`). The x64 configs lack these and likely won't build as-is. Release|Win32 uses toolset v141; the others use v143.
- Every `.cpp` must `#include "stdafx.h"` first (PCH). The bundled `ZLIB/*.c` files are set to `NotUsing`.
- New source files must be added to both `TRAODLE.vcxproj` and `TRAODLE.vcxproj.filters`.
- `Docs/Struttura_livelli_AoD.docx` (Italian) and `Docs/AoD_Level_Structure.docx` (English) are a human-readable overview of the level formats (diagrams, tables); the sister project TRAODLI (Level Importer, `D:\AoD\C++\VISUAL C++\TRAODLI`) has `HANDOFF_TRAODLE.md` describing how TRAODLE's scenes must be read back.
- `Release/` (gitignored) is also used as a scratch directory for test input files (GMX/MSH) and their outputs.
- `Release/<LEVEL>.log` (2003) are the original WorldEdit "Export manager" logs of the same levels (PARIS1 is a different version): per room the RMX node lists with buffer offsets, names and hashes; node message bindings (`Msg [n : NM_*] , Event [i : name]` = `RMX_MSG`); the ordered Object Template list (`RMX_OBJECT.ObjectIndex`); per zone the mesh names in index order with copies, collision bindings and dynamic flags; script sizes. The `[LOG]` tags in the `*_Struct.h` files refer to checks against them. The original names from these logs are embedded as the resource `IDR_AOD_NAMES` (`Resources/AoD_Names.txt`, regenerated by `Resources/make_AoD_Names.py`) and looked up by hash through `AOD_Names.h` (`AOD_NodeName`, `AOD_MeshName`, `AOD_EventName`, plus per-level `AOD_TemplateName`/`AOD_ScriptName`): a name is used only when its GetHashValue matches, otherwise the hash stays. They name RMX/ZONE rooms, RMX lights/water/PS2 objects/audio locators/waypoints, ZONE object instances (`rmxNode`, `objectTemplate` attributes) and meshes, SCX script files, and feed the script hash dictionary (`SCX_CollectHashNames`) used by the EVX/SCX text exports.
- `main.cpp` and `old_Zone_Exporter.h` are legacy files that aren't part of the build; the real entry point is `TRAODLE.cpp`. `TRAOD/Reference/Tools/` holds the original developers' tool sources and data that the project cites or uses (reference only, not compiled, not in the vcxproj): `Libs/AnimLib/AnimAPI.h`/`.c` (CAL/CHR runtime structures: ANIMATION, BONE, NODE, FXNODE, ...), `AnimEdit/EditorToGame.cpp` and `Morph.cpp` (CAL/TMT/TMS export), `Exporter/Export_Animation.cpp` (POS) and `map_msg.h` (NM_* messages), `ScriptProducer/` (SCX), `GMX Masher/` (GMX directory), `CollisionProducer/CollisionSpec.h` + `worldedit/Sys/collision.csc` (CLN attributes), `worldedit/Sys/effects.fsc` (emitter templates, read by `Resources/make_AoD_Names.py`), `Db2Game/db2game.cpp` (ACTOR.DB), `Vegas EDL Parser/` (CSS), `Map Messaging Tools In WorldEdit.doc` (EVX). `TRAOD/Reference/ProView/Debug.elf` is the PS2 development build of the game with stabs debug info (in `.mdebug`) and a symbol table: it gives the runtime struct definitions with field names, and the RMX nodes are those runtime structs (`tagMAP_BASENODE` 352 bytes + `tagMAP_TRIGNODE`, `tagMAP_FXNODE`, `ROOM_HEADER_TAG`, `tagMESH_HEADER` = `ZONE_OBJECT_INFO`, `tagMAP_SCENERY` = PS2_ROOM_OBJ/Fakes, ...); flag bits (`#define`s, not in stabs) were decoded by disassembling the MIPS code (e.g. `mapUpdateTrigger`). `[SRC: name]` gives the original field name. The `[SRC]` tags in the `*_Struct.h` files refer to them. The git-ignored `TRAOD/CHR/Reference_TRAODAE/` (full tool sources, old Animation Exporter, original Maya scenes) may be deleted: the project must not depend on it; copy into `TRAOD/Reference/` anything new that is needed.
- Encoding: many sources are ISO-8859-1 (Latin-1) with Italian accents in comments, all with CRLF. Editing tools that write UTF-8 corrupt the accents into U+FFFD; check `file <path>` before/after editing and keep Latin-1. New files should be plain ASCII + CRLF.
- Output testing: Maya 2016 and 2025 are installed; `"C:/Program Files/Autodesk/Maya2025/bin/mayapy.exe"` can open the exported MA/FBX headless to validate them (FBX import: `mel.eval('FBXImport -f "path" -t 1')`, take index is 1-based). The FBX writer must keep the `; FBX 7.5.0` comment consistent with `FBXVersion: 7500` and the GlobalSettings/PropertyTemplate entries, or recent FBX plugins reject the file or ignore animations. The FBX files are Z-up: import them into a Z-up Maya scene (`cmds.upAxis(axis='z')`) when comparing values, otherwise the importer's axis conversion changes the root node's curves. All MA files use `currentUnit -t ntsc` (30 fps, the AoD animation rate) and animations start at frame 0, so cameras (CAM) and CAL animations line up frame by frame. Joints use segment scale compensate (FBX `InheritType` 2, Maya default), as the TRAOD runtime does for tracks with `HASSSC`. With several skeletal takes in one FBX, Maya gives channels that have no curves in the imported take the values of another take, so `FBX_Write_SkeletalAnimation` writes a one-key curve for every T/R/S group that is animated in any other take of the file.

## Architecture

**Flow:** `TRAODLE.cpp::main` → `*_IO_Init(argv)` (fills a global IO object with paths and level name) → unpack container (`Decompress_CLZ`, `Export_GMX`, `Export_CLUSTER`) → iterate the extracted file list and dispatch by file type to `Export_<TYPE>(filename)`.

**Globals** (declared `extern` in `stdafx.h`): `AOD_IO`, `AE_IO`, `AODRemastered_IO` (classes in `Classes.h`: folder paths as both `string` and `LPWSTR`, the extracted file list, and `SearchFileIn*List` helpers), `TargetRenderer`, `msg_file_stream`, `mutex mu`. Code relies heavily on `SetCurrentDirectory` to the right output folder before writing files.

**Directory layout by game/format:**
- `TRAOD/<FMT>/` – AoD formats. Each has `<FMT>_Struct.h` (binary on-disk layouts read directly with `ifstream::read`), `<FMT>_Functions.h`, `<FMT>_Read*.cpp`, and `Export_<FMT>.cpp`.
- `TRAE/<FMT>/` – Anniversary Edition formats, same pattern.
- `TRAOD Remastered/MESH/` – Remastered mesh.
- `FBX/` and `MA/` – format-agnostic writers.
- `MATH/` – matrix/quaternion/rotation helpers (`math.h`).
- Root: shared helpers (texture decoders `Texture_*.cpp`, primitive builders `Draw*.cpp`, hashing, `Misc_Functions.h`).

**Export pattern (important):** readers don't write files. They fill two scene containers, `FBX_EXPORT` (`FBX/FBX_Classes.h`) and `MA_EXPORT` (`MA/MA_Classes.h`), with the shared scene classes from `Classes.h` (`Mesh`, `Material`, `Texture`, `Transform`, `Joint`, `Camera`, `Light`, `Locator`, ...). Then `FBX_Export(name, FBX)` and `MA_Export(name, MA)` serialize them. See `TRAOD/ZONE/Export_ZONE.cpp` for the canonical example. MA supports some Maya-only primitives (`PolyCube`, `PolyPlane`, `NurbsSurface`, `BossWave`, `Layer`). When adding a new scene feature, it usually has to be added to both writers. `Guida alle connections per file FBX.xlsx` documents FBX object connections.

**Logging:** use the `msg` macro from `OutMsgInterface.h` instead of `cout`:
```cpp
msg(msg::TGT::FILE_CONS, msg::TYP::WARN) << "text " << value;
```
`TGT` = FILE / CONS / FILE_CONS; `TYP` = OVR, LOG, DBG, WARN, ERR, FATAL. The macro captures `__FUNCTION__` for the log file. Export functions return `bool`. `false` gets logged as an error by the caller, and a fatal init failure goes through `Fatal_Error_Terminate()`.

**Resources:** `Resources/ColTex_*.tga` are collision-attribute textures embedded via `Resource.rc`/`resource.h` and written out with `SaveTGAResource` (used by the CLN exporter through `CLN_GetResource`).

**Version string** is `version` in `TRAODLE.cpp` (format `0.YYMMDD`).
